Privacy by Design

Privacy Policy

Effective Date: October 2026 • DataLens Architecture Reference

1. Core Philosophy: No Login, No Permanent Library

DataLens is architected from the ground up to minimize data retention. Unlike traditional SaaS analytics tools that require user registration, profile creation, and ongoing cloud storage of your datasets, DataLens requires no login, no signup, and no user accounts. We do not maintain a permanent dataset library.

2. What Data Is Processed

When you use DataLens, the application processes:

  • Uploaded Files: CSV (.csv) or Excel (.xlsx, .xls) files that you explicitly upload to the tool.
  • Statistical Aggregates: Row counts, column types, means, medians, missing rates, and data quality metrics computed locally via Pandas.
  • Analytical Queries: Questions entered into the "Ask Your Data" interface.

3. Temporary Processing & Lifecycle

Your uploaded dataset is treated strictly as ephemeral processing data:

  • Isolated Temporary Sessions: Each upload generates a cryptographically secure random session ID with its own isolated temporary directory in operating-system temporary storage.
  • Automatic TTL Expiration: Temporary analysis sessions automatically expire after 30 minutes of inactivity, after which all temporary files and in-memory caches are swept and deleted.
  • Explicit "Clear Session" Button: You can click "Clear Session" at any time to immediately destroy all server-side session files and wipe the browser workspace.
  • No Permanent Database: DataLens does not use a persistent database to track your dataset history or personal identity.

4. AI Provider Involvement & Data Minimization

When AI-assisted insights are generated:

  • No Raw Dataset Transmission: DataLens does NOT upload your raw CSV/Excel file or raw tabular rows to third-party file APIs.
  • Aggregated Context Only: Only high-level statistical summaries (e.g. column names, detected data types, averages, and missing counts) are provided to the Google Gemini API to produce natural language interpretations.
  • Offline Fallback: If no API key is configured or third-party connections are unavailable, DataLens automatically falls back to deterministic local rule-based analysis.
  • Sensitive Data Advisory: For strictly confidential, proprietary, or regulated data (e.g., HIPAA, PCI-DSS, personal PII), please review your organization's AI policies before triggering AI-assisted summaries.

5. Infrastructure & Security Boundaries

DataLens implements defense-in-depth measures including strict file-type validation, 25 MB upload limits, protection against path traversal attacks, and server-side secret management.

Important Technical Note: While DataLens is designed to minimize retention and eliminate account tracking, no web application can claim "100% absolute security" or "zero theoretical risk." Web traffic travels across internet routing hops, and third-party hosting platforms (e.g., Vercel, AWS) operate under their respective infrastructure security terms.

6. Questions & Contact

If you have questions regarding the technical privacy architecture of DataLens, refer to the project documentation in the repository or contact the project maintainer.
